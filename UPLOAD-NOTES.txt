── WHAT I DID WRONG ──────────────────────────────────────────────────────────
update-lastmod.ts --check is the FIRST thing npm run validate runs. It keeps a
hash of every page's own source in src/data/lastmod-manifest.json. Change a
page's content without shipping the updated manifest and the build stops:

    ❌ lastmod manifest is stale — 2 page(s) changed since it was last written.
       /average-golf-handicap/
       /golf-club-distance-chart/

I edited both pages and shipped neither manifest entry.

This was avoidable and I should have caught it. Sprint 184-190 — the sprint
immediately before this one — shipped src/data/lastmod-manifest.json for
exactly this reason. It was sitting in the file list I read while building 191.
The rule is simple and I now have it written down: if a sprint changes any
page's content, the manifest ships with it.


── WHY I COULD NOT JUST RUN npm run lastmod ──────────────────────────────────
You can't run npm locally and I have no checkout with node_modules. So I
reproduced the script's hash function exactly and verified it against known-good
values before touching anything:

  /golf-club-distance-chart/  is a bespoke .astro page with no ARTICLES record,
      so its hash is sha256(file)[:16].
      Old file -> 65a5081bea3ddfe1.  Manifest said 65a5081bea3ddfe1.  Match.

  /average-golf-handicap/  is an ARTICLES record with no .astro file, so its
      hash is sha256(JSON.stringify(record minus dateModified/datePublished)).
      Ran under node --experimental-strip-types so the serialisation is real
      JS JSON.stringify, not a Python approximation.
      Old record -> 1e6161592d6df3a3.  Manifest said 1e6161592d6df3a3.  Match.

Both reproduced the live values exactly, so the method is right, not merely
plausible. Then the new hashes:

      /golf-club-distance-chart/   65a5081bea3ddfe1 -> f9851296f7da03e8
      /average-golf-handicap/      1e6161592d6df3a3 -> 42c1c373517ae32b
      both lastmod -> 2026-10-20

The --check compares hashes, not dates, so the date is cosmetic to the
validator — but 2026-10-20 is also true, which is the point of the manifest.
