Sprint 205b — URGENT. The brand chart button text is invisible on all 6 pages.

EXTRACT AT THE REPOSITORY ROOT. 1 file.

  src/styles/global.css

No .astro changes, no manifest change. global.css is not hashed by
update-lastmod, so nothing else moves.


== THE BUG ===================================================================
On all six brand compression chart pages the "Open the full compression chart"
button renders dark green text on a dark green background. Measured on the live
Srixon page:

    computed color      rgb(30, 58, 40)
    computed background rgb(30, 58, 40)
    INVISIBLE           true

The label is there, readable by Google, invisible to a human.


== WHY ======================================================================
global.css carries this rule:

    .art-content a:not(.aff-cta__btn):not(.btn-gold):not(.rel-link)
      ... 14 :not() clauses ... { color: var(--green); }

Each :not() adds class-level specificity, so that selector sits around (0,15,1).
My .brand-chart-cta__btn is (0,1,0). It loses, and var(--green) is #1E3A28 —
exactly the button's own background.

The ORIGINAL pages had style="color:#fff" inline, which beat it. That is
precisely what validate-inline-styles warns about in its own header: "Inline
styles beat every class." Moving to classes was correct, but it dropped the
page into a cascade the inline style had been hiding.


== THE FIX ===================================================================
Added .brand-chart-cta__btn to the exclusion list on that rule, and on its
:hover partner so the underline colour does not come back. That is the pattern
this file already uses for every other button-shaped link inside .art-content —
aff-cta__btn, btn-gold, cmp-buy-btn, qp__cta and nine more.

After the exclusion the only rules matching the button are:

    a                       { color: inherit }        (0,0,1)
    .brand-chart-cta__btn   { color: #fff }           (0,1,0)   <- wins

Nothing else on the site carries that class, so no other page is affected.

it.

I only found it because I pulled computed styles on the live page afterwards.
That check — getComputedStyle on anything whose styling I moved — is what I
should run before zipping, not after pushing. It is one call.
