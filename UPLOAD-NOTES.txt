Sprint 203b — build fix. Four spacing values I put off the 4pt grid.

EXTRACT AT THE REPOSITORY ROOT. 1 file.

  src/styles/global.css

Nothing else changes. The six .astro pages and the manifest from Sprint 203 are
already in and correct — update-lastmod passed ("manifest matches all 301
pages") and all 301 pages built, including /vice-golf-ball-compression-chart/.
The build died at the very last validator.


== WHAT I DID WRONG ==========================================================
The Sprint 203 CSS block used:

    padding: 18px          margin: 26px 0
    padding: 10px 20px     margin-bottom: 6px

validate-spacing-scale enforces a 4pt grid with CEILING = 0 for CSS. Four
values, four failures, all mine:

    ❌ Spacing scale: 4 value(s) off the 4pt grid (ceiling 0).
       - 18px used 1× — nearest grid step is 20px
       - 26px used 1× — nearest grid step is 28px
       - 10px used 1× — nearest grid step is 12px
       - 6px used 1× — nearest grid step is 8px

Fixed by snapping each to the grid: 18→20, 26→28, 10→12, 6→8. Every px value
in the block is now divisible by 4 (8, 12, 16, 20, 28, 60). Verified by
extracting them and testing each.


== WHY I DIDN'T CATCH IT =====================================================
I copied those four values straight off the Srixon page, where they have lived
as inline styles since Sprint 100. I assumed values already on the site were
already compliant. They were not — they were merely somewhere else.

The validator has TWO ceilings:

    CSS files (global.css + .astro style blocks)  ceiling 0
    style="" attributes                            ceiling 395

The siblings' 18/26/10/6 have always been off-grid. They sat under the inline
allowance of 395, where there is headroom. Moving them into global.css — which
is the architecturally correct place and the thing that kept this sprint off
the inline-style ceiling — moved them to a ceiling of zero.

So the same decision that made the sprint safe on one validator is what broke
it on another. I checked the ceiling I had reasoned about and not the one I had
not. Next time I touch global.css I will grep my own block against the 4pt grid
before zipping, which is a two-line check.


== VISUAL EFFECT =============================================================
The Vice page will sit 2px different from its five siblings in four places
(box padding, box margin, button padding, FAQ question margin). Invisible in
practice, and it is the Vice page that is now on the house grid rather than the
siblings.

Worth knowing: migrating the other five pages to these classes, which Sprint
203 set up, would drain 40 from the inline-style ceiling AND pull four off-grid
inline values out of the 395 allowance.


== WHAT THE BUILD CONFIRMED ==================================================
Everything else in Sprint 203 was right, and the log proves two things I had
reasoned about rather than measured:

  "✅ lastmod: manifest matches all 301 pages"
     — the DATA_DEPS hashes I computed were correct, all six of them.

  "✅ Inline styles: 1225 literal style="" attribute(s) (ceiling 1225)"
     — the count is EXACTLY at the ceiling. Had I built the Vice page like its
       siblings it would have added 8 and failed. Using classes was not
       over-caution; it was the only way this sprint could have built at all.
