── WHY TWO IMAGES FOR THE DISTANCE CHART, ONE FOR THE HANDICAP ───────────────
13 clubs x 5 speed bands at 16:9 puts rows at ~33px and the type with them. A
carousel thumbnail is tiny; type nobody can read at that size wins the click
and loses it to a bounce. So the summary carries the 8 clubs that carry the
searches, at 25px, and the full version carries all 13.

The handicap table is 6 rows. One 16:9 holds all of it at 32px. A second file
would add nothing, so there isn't one.


── THE DRIFT PROBLEM, AND WHAT I DID ABOUT THE HANDICAP ──────────────────────
The distance images come from CLUBS and TIERS in club-distances.ts, so they
cannot disagree with the table. Same as compression coming from balls.ts.

The handicap figures have no data module — they live in an HTML table inside
the article's section body. Copying them into the generator would be exactly
the drift Sprint 131 was written about (the hand-written compression embed
shipped TruFeel at 45 for months after the table said 70).

So the generator PARSES that table out of the record. If it finds anything
other than six age bands with numeric values, the build STOPS with a message
naming the problem. I tested that: deleted the 70+ row and re-ran —

    ❌ generate-handicap-chart-image: expected 6 age bands, parsed 5
    exit code: 1

A silent fallback would draw a chart that no longer matches the page, which is
the one failure the whole generated-art approach exists to prevent.


── I ACTUALLY RAN THESE, AND LOOKED AT THE OUTPUT ────────────────────────────
I installed sharp in my sandbox and ran both generators for real rather than
shipping untested code into the build chain — which is how I broke the build in

  3. On the full chart the subtitle ran into the column header row.
  4. On the full chart the "115 MPH" header collided with the "ROLL" header.
  5. And the 115 MPH numbers ran into the "+20 roll" text beside them.

── NO NEW INLINE STYLES ──────────────────────────────────────────────────────
validate-inline-styles caps literal style="" at 1225 and only ever lets it
fall, so a figure styled the way Sprint 135 styled its one would have pushed
the count over and failed the build. The treatment went into global.css as
.chart-figure instead — which is what the ratchet's own note says to do with a
repeated style.

    index.astro   39 style="" before, 39 after
    articles.ts    7 style="" before,  7 after

Width needed nothing: `figure` is already in the Sprint 151b exclusion list
("a table, a spec grid, a product grid and a figure exist to put values side by
side — width is the whole point of them"), so a figure already earns the shell.


── BUILD ORDER — CHECKED, NOT ASSUMED ────────────────────────────────────────
Both generators read src/ and write public/, so they belong BEFORE astro build,
and that is where they sit.

There is a trap here I nearly walked into: generate-DISTance-chart-image.ts
contains the substring "dist". validate-build-order looks for scripts reading
dist/ in the pre-build chain. I ran it against this package.json rather than
reasoning about it:

    ✅ Build order: 62 pre-build step(s) checked — none reads dist/ unguarded.

Its regex matches a quoted `('dist'` or `'dist/` in a script's SOURCE, not a
filename, and neither generator contains any dist literal at all. Verified both
ways.
