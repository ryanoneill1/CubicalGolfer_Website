── WHAT I DID WRONG ──────────────────────────────────────────────────────────
Sprint 196 updated two manifest entries, for /golf-ball-complete-guide/ and
/golf-simulator-complete-guide/, and wrote them into sprint-196-build.

I then built Sprint 197 from sprint-192-build — a different folder, which did
not have Sprint 196's manifest changes. So Sprint 197 shipped a manifest with
the PRE-196 hashes for those two pages, while their .astro files in the repo
still carry Sprint 196's content. update-lastmod compared the two and correctly
reported them as changed:

    ❌ lastmod manifest is stale — 2 page(s) changed since it was last written.
       /golf-ball-complete-guide/
       /golf-simulator-complete-guide/

This is the "don't lose anything" failure in its purest form: a whole-file
manifest built on a stale base silently reverted work from the sprint before.
It is the second time lastmod has broken a build in this run, and this time the
cause was entirely mine rather than an omission.

The fix is four lines — two hashes and two dates restored:

    /golf-ball-complete-guide/        a4778069048435aa -> 76f13008bfb5d492
    /golf-simulator-complete-guide/   d66630bcd5cf0daa -> 6b276c998ca41082

Diffed against exactly what you pushed: 4 changed lines, nothing else, 300
entries before and after.


── ROOT CAUSE, AND WHAT I CHANGED ABOUT HOW I WORK ───────────────────────────
I have been building each sprint from whichever previous sprint folder happened
to hold the file I needed — 192 for articles.ts, 196 for the guide pages, 194
for the slug template. That works until two sprints touch the same whole-file
artifact, and then the older base wins and quietly undoes the newer work.

I have now built a single canonical CURRENT/ folder holding the true current
state of every file I manage, assembled from the deployed lineage:

    src/data/articles.ts                 191,192,193,194,195 + 197
    src/data/lastmod-manifest.json       all of the above + 196 restored
    src/pages/golf-ball-complete-guide/        196
    src/pages/golf-simulator-complete-guide/   196
    src/pages/golf-club-distance-chart/        191,192
    src/pages/[...slug].astro                  194
    src/styles/global.css                      192
    package.json, scripts/                     192

Every future sprint gets built from CURRENT and written back to it. That
removes the class of error entirely rather than me remembering not to make it.
